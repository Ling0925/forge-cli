# 终端选区与复制

- 普通单击不再建立选区或暂停显示；拖动才建立 Forge 选区。再次单击或 Esc 清除选区并追上最新输出。
- Forge 选区保存所选文本快照，选中的消息区暂不滚动；未被选中的底部状态行继续刷新，不再整屏冻结。选中输入行时该行保持快照；输入或 Esc 可退出。
- **默认直接拖选，松开鼠标自动复制**：发送一次 OSC52 请求，清除选区并恢复刷新；输入区上方短暂显示 `Copyed！`（1.5 秒），无需额外按键。单击不复制，空/超限选区显示失败。拖动尚未结束时仍可 Ctrl+C 提前复制。
- `Copyed！` 是发送回执，不是 OS 剪贴板确认；终端必须允许 OSC52。正常使用不需要切模式，下面的原生模式仅保留作不支持 OSC52 时的可选备用。
- 如果 OSC52 无效：按 **Ctrl+G** 进入原生选择模式，关闭应用鼠标捕获并明确暂停画面刷新。随后用鼠标选中文字，通过终端的复制菜单或其复制快捷键（常见为 Ctrl+Shift+C，macOS 常见 Cmd+C）复制。
- 再按 **Ctrl+G** 恢复。Esc/普通输入键也会先退出原生选择模式，该次按键不提交草稿或取消任务。后台任务并未暂停；恢复时显示积累输出。
- 审批开始会强制退出原生选择模式以显示审批；审批/picker 中 Ctrl+G 不切换模式。粘贴中的 Ctrl+G 不启用模式。
- 仍支持终端常见的 Shift+拖选绕过鼠标捕获，但具体复制键取决于终端配置。原生模式不调用操作系统剪贴板程序，不读取剪贴板。

本轮聚焦回归覆盖单击、拖选期间状态刷新、选区快照复制、原生模式进出、审批可见性、粘贴边界；xterm/Chromium 测试验证选中行不变且 Working 状态继续刷新。真实用户终端的 OSC52 和 OS 剪贴板能力没有在本机自动测试中确认。
